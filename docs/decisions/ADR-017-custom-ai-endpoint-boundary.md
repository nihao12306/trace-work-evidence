# ADR-017：自定义 AI 端点必须在发送前确认范围

## 背景

Trace 需要允许用户接入自己控制的模型服务，但公开静态站点不能安全保存供应商密钥，也不能把“点击整理”误解为“自动把所有工作资料发出去”。记录、周报和项目案例的输入范围不同，必须在任务发生前让用户知道本次会发送什么。

## 决策

1. AI 设置分为关闭、无网络演示和自定义端点三种模式。
2. 自定义端点只接受用户主动保存的 HTTP(S) 地址；Trace 不保存或代填 API Key，不提供代理，不负责 CORS、认证、限流或端点侧留存。
3. 每个自定义 AI 入口都要在请求前展示任务范围、记录/证据数量和发送内容类型，并由用户在浏览器确认对话框中主动确认；取消确认不得发出请求。
4. 端点使用 `trace-custom-ai` JSON 协议返回结构化 `proposals`。适配层先做 schema 校验，应用服务随后校验引用、栏目和候选状态，任何失败都不写入半成品。
5. AI 运行记录只保存任务、适配器、模型标签、Prompt 协议版本、输入引用、状态和输出实体 ID，不默认保存完整请求/响应。

## 后果

- 用户清楚知道哪些材料会离开当前浏览器，且可以拒绝发送。
- 自定义端点能在本地代理、公司内网或个人服务中实现，不把 Trace 绑定到某一家供应商。
- 浏览器跨域和端点鉴权需要用户自行配置；这是一项明确的部署前提，不由 Trace 隐藏处理。
- 演示模式仍然完全离线，未配置 AI 时记录、证据、周报、案例和导出闭环不受影响。
