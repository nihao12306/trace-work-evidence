# ADR-020：先从经历推导岗位方向，再用偏好筛选

日期：2026-09-05  
状态：已确认

## 背景

0.2.0 的求职页要求用户先填写候选方向，再把经历组织成分析包。这与产品作者确认的核心需求相反：Trace 应先从已有经历中总结用户能做什么岗位，而不是让用户先给出岗位答案后再改编经历。

岗位方向仍然是推断，不是事实。产品既要提供主动发现能力，也必须保持证据可追溯、不得夸大和不得自动确认的边界。

## 决策

1. 求职页先读取已确认经历、已确认能力主张和项目上下文，识别重复出现的工作信号；
2. 一个岗位族候选至少需要两个相互支持的来源和两类工作信号，其中必须包含行动、决策或已确认能力主张；假设、待确认、已拒绝和单条孤立经历不参与推导；
3. 每个候选展示具体支持经历、反复出现的信号，并只标注“初步线索”或“较强线索”；
4. 用户填写的当前岗位、偏好、约束、排除项和方向反馈只用于后续筛选，不参与候选方向计算；
5. 候选即时计算、不持久化，不生成竞争力分数，不等同于实时招聘市场匹配或最终职业建议；
6. 导出包先列证据和系统推导方向，再要求后续分析者用用户条件筛选，禁止用目标岗位反向改写经历。

## 后果

- 用户不需要先知道目标岗位，也能看到一版有依据的方向发现结果；
- 未配置 AI 时仍可使用可复现的岗位族推导；
- 岗位族规则只能覆盖第一批常见知识工作方向，细分职位、行业适配和招聘市场供需仍需后续分析；
- 增加或调整岗位族规则时必须补测试，避免单条关键词触发无依据推荐。
