# ADR-013：项目案例采用显式证据范围

## 状态

已接受（2026-08-13）

## 背景

项目案例是证据进入长期表达的第二个出口。它不能把一个项目下的所有材料自动拼成“能力故事”，也不能因为用户选择了一个项目就暗示项目结果已经完整。

## 决策

第一版的项目案例必须同时保存：

- 所属项目；
- 用户选择的开始日期与结束日期；
- 纳入的已确认 `EvidenceItem` ID；
- 在候选范围内被排除的证据 ID；
- 固定七段结构：背景、问题、判断、行动、迭代、结果、形成的能力。

创建和修改证据范围时，只有项目一致、日期在范围内且已确认的证据可以被选择。原始记录、证据和引用不会因为排除而删除。

七段内容由用户逐段写下、选择认识论类型并确认。`结果` 使用事实类型时必须有有效引用；七段全部有内容且已确认后，才能定稿。定稿后修改创建新修订，旧版本保持可回看。

“形成的能力”在这一阶段只是案例中的一个由用户书写的段落，不会自动创建 `CapabilityClaim`，也不会因为案例定稿而生成跨项目能力结论。

## 取舍

- 显式日期和证据选择增加了一步操作，但能让用户知道案例为什么包含这些材料。
- 固定七段提供写作支架，却不承诺每个案例都有可证明的能力；空白和待确认状态必须被看见。
- 目前案例编辑与定稿已可用，Markdown/打印 HTML 的案例导出和能力主张沉淀留在后续阶段。

## 影响

- `CaseStudy` 保存 `rangeStart`、`rangeEnd`、`includedEvidenceIds` 与 `excludedEvidenceIds`。
- `CaseStudyRevision` 复用 `OutputBlock`，沿用周报的逐块确认、引用和修订规则。
- 项目案例成为独立入口，不把项目列表、证据列表直接当作案例导出。
