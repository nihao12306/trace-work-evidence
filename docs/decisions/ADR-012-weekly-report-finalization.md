# ADR-012：周报定稿采用不可覆盖修订

日期：2026-08-13  
状态：已确认，第一版实现

## 背景

周报不是一次性导出动作。用户需要在组稿、确认、定稿之间往返；如果定稿后继续编辑直接覆盖原内容，之后无法解释“当时最终确认了什么”。

## 决策

- 周报当前修订可以处于草稿或已定稿状态；
- 定稿前，所有内容块必须已由用户确认；事实性内容块必须保留有效来源；
- 定稿生成新的周报修订，旧草稿和内容块不被覆盖；
- 定稿后的“继续修改”会复制当前内容块，建立新的草稿修订；用户修改副本不会改变旧定稿；
- 周报页面可以切换查看历史修订，历史修订只读；
- 手动添加事实性内容时，必须先选择本周有效原文来源；没有来源时可以写用户判断或假设，但不能把它定稿为事实。

## 被放弃的选项

### 直接把定稿状态写回当前内容块

实现更简单，但会破坏历史可追溯性，也无法解释旧周报为什么和后来导出的内容不同。

### 定稿后禁止任何修改

会让周报成为一次性文件，用户只能复制整份内容重新开始，无法持续修订表达。

## 后果

- 数据模型需要保留周报修订与内容块的关系；
- 页面需要明确区分“查看历史版本”和“继续修改”；
- 导出默认使用当前选中的修订，历史版本仍可回看；
- 复制修订会增加对象数量，但换来稳定的审计关系和更诚实的工作记录。
