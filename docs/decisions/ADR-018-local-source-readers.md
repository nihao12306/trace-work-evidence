# ADR-018：本地伴侣读取 Codex 会话与飞书导出目录

日期：2026-08-18  
状态：已确认，第一版实现

## 背景

Trace 的价值不只来自用户手动补写记录：用户希望它能回看自己已经产生的 Codex 工作和飞书材料，再把这些原始痕迹整理成证据。与此同时，第一版不部署 OAuth 后端，也不能把飞书密钥或 Codex 凭证写进公开前端。

## 决策

本地伴侣增加两个只读来源适配器：

- Codex：读取用户明确配置的 Codex 根目录下 `sessions` 与 `archived_sessions` JSONL；只提取用户消息和 Codex 最终消息，形成带 `codex://session/...` 定位符的原始材料；
- 飞书：读取用户明确配置的本地导出/同步目录中的 JSON、Markdown 和文本文件；不通过浏览器登录在线账号；
- 两类来源都必须经过范围选择、预览、勾选和确认后才能写入 Trace；
- 写入后可以主动生成“保守证据草稿”，草稿带原文引用且必须由用户确认；
- 伴侣不读取 `auth.json`、SQLite、日志、memory、附件图片或其他未列入适配器范围的文件；
- 伴侣不后台持续同步、不上传作者服务器、不保存任何凭证。

## 为什么不是直接读在线飞书

在线飞书读取需要官方应用授权、令牌生命周期、撤销、权限解释和持续安全维护。没有 OAuth 后端时，浏览器无法安全承担这些职责；因此第一版把“能读取用户自己的资料”收敛为本地导出/同步目录。未来若要在线连接，必须新增独立 ADR，不能把环境变量读取悄悄改成 OAuth。

## 后果

- 用户首次配置需要设置 `TRACE_FEISHU_EXPORT_DIR`；Codex 通常可自动检测 `%USERPROFILE%\\.codex`；
- Codex 会话文件不是面向第三方的稳定公共 API，适配器必须保持保守解析，格式变化时宁可报错或不给预览；
- 预览可能包含敏感原文，因此默认只在本机 localhost 通信，页面必须明确显示读取范围；
- Trace 的证据、周报、案例和能力主张仍然遵循“原始记录 → 引用 → 用户确认”的链路，读取来源不会改变事实确认规则。
