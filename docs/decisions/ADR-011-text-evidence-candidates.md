# ADR-011：原始文字先经过保守规则整理，再进入人工确认

日期：2026-08-12  
状态：已确认，第一版实现

## 背景

用户最容易留下的是一段未经整理的工作原话。如果只有补充字段才能生成证据，产品会把“先记录下来”的低门槛重新变成结构化表单负担。与此同时，直接让模型把原话改写成事实，会让 Trace 失去证据优先和认识论区分。

## 决策

第一版在没有 AI 配置时，也提供“从原始文字提炼证据表达”入口。它使用领域层的纯函数规则适配器，把“原文依据”和“可复用的证据表达”分开：

- 只在原文句段中识别行动、问题、决策、结果、反馈、学习和假设的候选；必要时把相邻、同一判断链的片段合并成一条表达；
- `statement` 是整理后的证据表达，`Citation.quoteSnapshot` 是原文依据；不能把切出来的原句直接伪装成整理结果；
- 每条候选保留原文摘录、当前修订和字符范围；
- 结果类候选排除“可能、假如、预计”等条件或推测表达；
- 候选由系统标记为“结构候选 / 待你确认”，不会自动成为已确认事实；
- 用户可以编辑、确认或拒绝；拒绝仍保留来源与历史状态；
- 同一记录、同一修订和同一原文摘录重复整理时不重复写入；
- 规则宁可少提取，也不凭空补写结果、数据或能力结论；旧版仅切句候选只能由用户主动触发重新整理，合并时保留被合并项的拒绝历史。
- 已经确认的旧版原文直出候选不做静默迁移；界面明确标记为“原文直出（旧版候选）”。用户主动触发重新整理并确认影响后，可以保留确认状态地改写同一引用支持的表达，重复项移入历史。

## 被放弃的选项

### 只有手动填写结构字段

实现简单，但无法兑现“先留下碎片、再逐步沉淀”的核心路径，会鼓励用户一开始就写成表单答案。

### 默认调用模型改写整段原文

表达可能更流畅，但无法保证每个判断都能回到原文，也会增加未配置 AI 时的阻断和公开演示的密钥风险。未来 AI 适配器可以复用同一候选、引用和确认协议，但不能绕过这些状态。

## 后果

- 原始记录可以直接进入证据整理，而不要求用户重复填写字段；
- 规则候选可能有误判，产品必须让拒绝和编辑与确认同等显眼，并持续通过真实中文记录校准规则；
- 规则适配器不是语义理解的承诺，不能在界面上称为“AI 总结”；
- 周报、项目案例和能力证明只能消费已确认且有有效来源的内容。
