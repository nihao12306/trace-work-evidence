# ADR-021：求职分析主动寻找本机工作记录

日期：2026-09-05  
状态：已确认

## 背景

仅分析已经进入 Trace 的证据仍要求用户预先整理材料，不符合产品作者确认的自动化目标。完整需求是：Trace 主动从已经授权的工作来源寻找记录与成果，再归纳能力并推导可能岗位。

浏览器不能也不应直接遍历本机文件。现有本地伴侣已经提供只读 Codex 会话和飞书本地导出目录的范围预览协议，因此求职自动发现应复用这条边界，而不是增加后台全盘扫描。

## 决策

1. 求职页提供“自动扫描工作记录”，默认范围为最近一年，也允许最近 90 天或全部历史；点击按钮是本次读取的明确授权；
2. 一次扫描所有已配置且可读的 Codex、飞书本地来源，在写入前展示来源、日期、标题和规则识别的工作信号；
3. 自动选择最多 30 条含行动、判断、结果或反馈的未导入材料，用户可逐条取消；
4. 用户再次确认后才导入原始记录，并自动生成带引用、状态为 `proposed` 的证据候选；
5. 用户必须逐条确认候选，只有已确认内容才能参与岗位方向推导；
6. 不做后台扫描，不读取凭证、数据库、日志或未配置目录，不向外部服务发送材料；
7. 增加 `npm run start:local`，同时启动网页与本地伴侣，降低真实使用门槛。

## 后果

- 用户不需要先手工制作分析包或逐条复制工作经历；
- 首次扫描仍需要启动本地模式，并在预览后确认导入，这是本地文件访问和事实确认的必要边界；
- 规则只能先发现文本中明确出现的行动、判断、结果与反馈，图片、附件、语音和在线飞书内容仍不在范围内；
- 更智能的语义召回可以后续加入，但必须继续遵守预览、引用和人工确认边界。
